# NovaOrg 架构

## 1 任务和模型边界

TaskPlanner 将诉求转换成明确的业务意图与岗位步骤，工具范围由确定性代码约束。AgentStepExecutor 使用原生模型消息历史和工具结果回灌，按停止原因区分完成、待审批、待补充和预算/协议失败。

## 2 工具与数据

RoleGuard 校验工具登记、步骤范围、角色权限、参数与高风险审批。待审批参数和版本冻结后落库，批准时执行快照，不再询问模型。数据库事务、行锁、退款业务键和余额约束控制并发、重复和超额。

ClasspathKnowledgeBase 按标题切块，基于岗位命名空间过滤；InMemoryHybridIndex 做 BM25、向量与领域概念排名并用 RRF 融合。真实 embedding 通过端口适配，维度/非数值/异常响应明确失败。本地哈希仅用于离线演示，不被标成语义模型。

## 2.6 可选 Spring AI 适配器

默认 LlmPort 使用直接 HTTP 适配器实现原生 Function Calling。`springai` Maven profile 添加可选 SDK 适配器与相应源码，运行 `mvn -Pspringai test` 才包含这些可选代码；默认构建不会要求 SDK 的模型密钥。本文不宣称该适配器已经验证了和默认端口相同的全部真实多轮能力。

## 3 评测边界

软件回归使用模拟或规则模型。真实聊天和仅检索评测分开运行，报告保存后端、语料/提示词 hash、usage 与轨迹。文档级 Hit@k 不等于回答准确率；合成留出查询仍需人工审核，历史批次不能合并成最终配置的成功率。
