# GLM Embedding-3 接入与检索对比

## 已完成

用户提供本机密钥文件后，已接入智谱 `embedding-3`，端点为 `https://open.bigmodel.cn/api/paas/v4/embeddings`，显式指定 1024 维。密钥通过 Windows DPAPI 加密保存在 .local/api-config.json，没有写入源码、报告或日志。此前 DeepSeek 聊天配置保留。

当前 http://127.0.0.1:8093 已运行最新 jar，健康检查 UP；登录后的 /api/system 返回真实 DeepSeek 后端与 `learned-embedding:embedding-3@open.bigmodel.cn/1024d`。10 份制度文档共 40 个知识块，以内存精确余弦检索，不需要为当前规模引入独立向量数据库。

接口实现依据 [智谱官方 Embedding-3 文档](https://docs.bigmodel.cn/cn/guide/models/embedding/embedding-3)：支持指定维度，使用 Bearer 密钥。当前每批最多 16 条文本，块大小最多 420 字符；返回结果按 index 对齐，校验维度、数值有限性和非零向量。失败直接报错，不自动降级为哈希向量。进程内最多缓存 2048 段文本；重启会重新向量化知识库。

## 结论与取舍

真实语义向量在这批口语查询中已有帮助，但 RRF 融合没有全面超过单通道：当前默认融合在留出集的首位命中从 BM25 的 13/20 提高到 15/20，前 3 命中仍是 18/20；纯语义通道前 3 命中为 20/20。人工概念不是越加越好，启发式 rerank 也没有稳定收益。

本次保留原有三通道默认和关闭 rerank 的设置，完整保存对比，避免看完留出集再为这个小集合反复调参。后续更有价值的工作是人工复核标签、补充新的独立查询，以及覆盖真实业务边界的制度；当前不应把扩成 200 份文档当成效果保证。
